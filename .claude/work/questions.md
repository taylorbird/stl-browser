# Resolved

- Thangs scraped images not saving to the library — RESOLVED 2026-07-16: root cause was `downloadImage()` in `api/src/routes.js` rejecting responses whose Content-Type was `application/octet-stream` — Thangs images are GCS-hosted and served with that generic content type rather than an `image/*` MIME type, so they were silently skipped. Fixed by trusting a known image extension parsed from the URL (with `decodeURIComponent` on the filename) when content-type is uninformative. Regression test added; full suite 106/106.
- 'The Rail v2' model saved with no images — RESOLVED 2026-07-16: rebuilt via the live API after the image-download fix above (old id 34821 deleted; new id 36163 created with all 10 images).
- 'Recently added' shelf not showing a just-added model — RESOLVED 2026-07-16: it filtered on publish date (`m.date`), not add time. Added a dedicated `added_at` column (db.js migration + indexer sets it on insert, preserves it on update) and switched the filter/count in routes.js to use it — `indexed_at` was unusable for this since it gets overwritten on every startup reindex. Verified live.

This supersedes the "uncommitted on main" note in the Thangs importer entry below — the importer work is now committed (to the Mac repo specifically); push status is still open (see new open question above).
- Thangs live verification BLOCKED on Tailscale/network connectivity — RESOLVED 2026-07-14: resolved not by fixing the Tailscale path to `browserless.thebirds.casa`, but by the user providing a different, directly-reachable browserless endpoint (`http://10.33.103.126:4100`, a LAN-local IP) plus an auth token (shared in chat only, not written to any file). Reachability and auth were verified, then the full live Thangs scrape succeeded end-to-end through it. That live run surfaced two real, previously-undetected bugs (only found because live verification finally succeeded): (1) a quote-stripping regex bug in `addModel.js`'s attribute-value extraction (`["']([^"']*)["']` excludes both quote characters from the match, so any attribute value containing an apostrophe — e.g. `content="I've had..."` — got truncated at the apostrophe; silently broke Thangs' scraped `description` and could affect any site's og:image/title/alt/src values with an apostrophe) — fixed via a new `attrValue()` helper using a regex backreference to the actual opening quote, applied everywhere the old pattern was used. (2) Thangs renders its own auto-generated 3D-viewer preview thumbnail with the exact same `alt` text as the real designer-uploaded gallery photos, served from a different GCS bucket (`thangs-thumbnails` vs `production-thangs-public`) and that duplicate is a dead 404 link on Thangs' own storage — fixed by excluding `/thangs-thumbnails/` URLs from the images array in `thangs.js`. 104/104 tests re-verified passing. See new open question above re: whether the LAN IP endpoint is the long-term BROWSERLESS_URL or just temporary.
- Next site importer (Printables vs Thangs) — RESOLVED (choice made) 2026-07-14: Taylor chose Thangs when asked directly. Importer built following the existing registry pattern (`api/src/importers/thangs.js`, registered in `index.js`): title/creator parsed from `og:title` (split on " - 3D model by ... on Thangs"), publish date from the embedded Next.js `__NEXT_DATA__` JSON blob, images filtered to the hero + thumbnail strip via exact `alt` match — verified against a real rendered page/screenshot. Thangs blocks plain HTTP fetches with a Cloudflare Turnstile challenge (verified via curl: 403 "Just a moment..." shell), so this importer needs a headless-browser render step — unlike Patreon, where server HTML carries full OG tags and plain fetch suffices. Per Taylor's explicit requirement ("I don't want to use browserless for an importer unless we have to"), this is implemented as an opt-in `render: true` flag on the importer object (only Thangs sets it) routed through a new `api/src/browserless.js` client hitting Taylor's self-hosted browserless instance. Full test suite 104/104 passing (+5 Thangs tests; also fixed a pre-existing test fixture that used `thangs.com` as a "no importer matches" example, now swapped to `printables.com`). All changes uncommitted on main as of 2026-07-14. Live end-to-end verification against the real Thangs site subsequently completed this session — see resolved entry above.
